# vBook 业务规划书

## 项目愿景

vBook 的目标是把股票/交易类视频课程自动整理成“图文一体、结构化、可检索”的知识资产。它不仅要听懂讲师说了什么，还要看懂视频画面中出现的 PPT、K 线案例图、行情截图和关键标注。通用课程能力是后续扩展方向，但第一阶段服务股票课程优先。

## 业务问题

传统视频转文字流程只能保留语音内容，但股票课程中的关键知识经常出现在画面中。K 线图、买卖点标注、支撑压力位置、均线形态和 PPT 要点如果没有被提取，最终笔记会缺少核心证据和案例上下文。

## 目标用户

- 希望把股票/交易课程沉淀成复习笔记的学习者。
- 需要跨课程检索战法、形态和案例素材的课程学习者。
- 希望保留截图、时间戳、讲解文本和知识结论的知识管理用户。
- 对 K 线案例、买卖点讲解和实战截图依赖较强的交易课程用户。

## 核心价值

vBook 应让用户在复习一个知识点时，同时看到讲解摘要、相关截图、原视频时间点和可追溯的文字来源。用户不需要反复打开完整视频，也能理解课程中的关键案例。

## 输入与输出

输入包括课程视频、已有带时间戳转写文本、课程名称、章节标题和标签。MVP 的标准输入是“视频 + transcript”；可选通过外部 `vtext` CLI 生成 transcript，但 vBook 不依赖 vtext 包。

输出以 `note.md` 和 `manifest.json` 为双核心：`note.md` 给用户阅读，`manifest.json` 给复跑、审计和后续知识库使用。同时保存关键帧图片、多模态视觉分析结果、OCR fallback 结果和图文时间轴对齐数据。

## MVP 范围

第一版可用产品应处理单个股票课程视频，优先识别 PPT 和 K 线案例图，输出带截图引用的 Markdown 笔记和 manifest，并保留完整中间产物。它不需要 Web UI、生产级服务端、向量数据库、交割单识别或复杂表格识别。

## 与 vtext 的关系

vtext 是 vBook 的架构参考，尤其是 Python 包结构、CLI/server/common 分层、配置优先级、任务队列、进度反馈和文档组织方式。vBook 不能在运行时 import、vendor 或依赖 vtext 代码。需要复用的能力必须沉淀为 vBook 自有接口。

## 成功标准

- 用户只读文档即可理解 vBook 的业务闭环和技术路径。
- 最终笔记能回溯到视频时间戳、PPT 截图和 K 线案例图。
- 中间产物可检查、可缓存、可复跑。
- 架构能从本地 CLI 平滑演进到 client/server 模式。

# vBook 业务规划书

## 项目愿景

vBook 的目标是把视频课程自动整理成“图文一体、结构化、可检索”的知识资产。它不仅要听懂讲师说了什么，还要看懂视频画面中出现的 PPT、图表、案例截图、代码和表格。

## 业务问题

传统视频转文字流程只能保留语音内容，但课程中的关键知识经常出现在画面中。比如股票课程里的 K 线图、交易案例、回测表格和 PPT 要点，如果只做转写，最终笔记会缺少核心证据和案例上下文。

## 目标用户

- 希望把长视频课程沉淀成复习笔记的学习者。
- 需要跨课程检索知识点和案例素材的课程学习者。
- 希望保留截图、时间戳、讲解文本和知识结论的知识管理用户。
- 对股票案例、图表讲解和实战截图依赖较强的课程用户。

## 核心价值

vBook 应让用户在复习一个知识点时，同时看到讲解摘要、相关截图、原视频时间点和可追溯的文字来源。用户不需要反复打开完整视频，也能理解课程中的关键案例。

## 输入与输出

输入包括课程视频、可选的已有转写文本、课程名称、章节标题和标签。

输出包括 Markdown 笔记、关键帧图片、OCR 或多模态视觉分析结果、图文时间轴对齐数据、结构化 JSON manifest，以及后续可用于知识库检索的索引数据。

## MVP 范围

第一版可用产品应处理单个视频，输出一份带截图引用的 Markdown 笔记，并保留完整中间产物。它不需要 Web UI、生产级服务端或向量数据库。

## 与 vtext 的关系

vtext 是 vBook 的架构参考，尤其是 Python 包结构、CLI/server/common 分层、配置优先级、任务队列、进度反馈和文档组织方式。vBook 不能在运行时 import、vendor 或依赖 vtext 代码。需要复用的能力必须沉淀为 vBook 自有接口。

## 成功标准

- 用户只读文档即可理解 vBook 的业务闭环和技术路径。
- 最终笔记能回溯到视频时间戳和图片资产。
- 中间产物可检查、可缓存、可复跑。
- 架构能从本地 CLI 平滑演进到 client/server 模式。
